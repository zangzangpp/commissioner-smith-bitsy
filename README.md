# 史密斯专员 vs 国会老爷

**Commissioner Smith vs Congress** 是一款已经完成的原生 Bitsy 政治讽刺游戏：采购 100 把椅子，原报价 $2,000，开局要求节约公共开支；国会却需要两位议员签字。所有人物、机构细节与事件均为虚构。

## 在线入口

- 网页游玩：[GitHub Pages](https://zangzangpp.github.io/commissioner-smith-bitsy/)
- 源码与文档：[GitHub 仓库](https://github.com/zangzangpp/commissioner-smith-bitsy)

## 直接游玩

解压整个文件夹，双击 `index.html`，使用 Chrome、Edge、Firefox 或 Safari 打开即可。运行资源与 Bitsy 引擎都在 HTML 内，不需要联网、安装软件或启动服务器。游戏正文为英文。

- 方向键或 WASD：移动。撞向人物、立着的文件或标牌：交谈／阅读。
- 空格或方向键：继续文字；第一次按键可能只会补全文字，下一次才翻页。
- 发光的散页：走上去收集。开局文件在办公室内；原始报价在承包商办公室。
- **重要决定要互动两次**：第一次预览费用、签字与后果；读完后再次撞向同一文件才执行。预览其他文件会改为另一项待确认决定；确认后清除待确认状态。只读人物不会确认交易。
- 手机：Bitsy 原生触摸操作，滑动移动、点按继续；已完成桌面键盘验证，手机触摸仍建议展示前用实际设备试一次。
- 点击页面下方 **Restart game** 从头开始。结局文字结束后，Bitsy 原生输入也可以开始新一局。

任务、预算和结局都运行在原生 Bitsy 引擎中。HTML 外壳只提供说明、数据下载链接与重载按钮，不决定游戏规则。

## 找路与账本

共有 8 个房间。办公室北门进入大厅；大厅南门回办公室，北门去听证会，西上门去承包商，西下门去公共档案室，东上门去 Doran，东下门去 Bell。公共档案室北门通往私下交易休息室。

开始先取办公室文件，再取承包商报价，之后其余区域开放。大厅的 Clerk Vale 说明门的位置。所有房间都能返回；没有必须接受交易才能离开的机关。办公室桌边的账本可随时查看预算、签字、承诺、个人现金和下一步；听证会书记员会明确说明当前方案会触发哪个结局。

房间地图是 16×16，画面格子为原生 8×8 像素。桌子、书架、植物和椅子阻挡移动；可绕行。人物与立着的文件要从相邻位置撞向它们。

## 预算与选择

| 方案 | 公共预算变化 | 支持与后果 |
|---|---:|---|
| 原始采购 | $2,000 起始预算 | 100 把普通办公椅 |
| 承包商 STAR 文件 | +$8,000 | 高价“战略级人员支撑平台”，不增加签字 |
| Doran 的 FACTORY 文件 | +$6,000 | 选区工厂承诺，获得 Doran 签字 |
| Bell 的 TRAINING 文件 | +$24,000 | 培训中心承诺，获得 Bell 签字 |
| 私下 ENVELOPE | 公共预算不变 | 史密斯个人获得 $500，不增加签字，不能撤销 |
| 私下 RETURN | 不变 | 永久拒绝个人现金；已拿现金后无法用此文件撤回 |
| 承包商 PLAIN 文件 | 重置为 $2,000 | 移除全部公共附加项目，并撤销两位议员签字；保留已接受现金的记录 |

每项加价、签字、现金奖励都只能生效一次。恢复原方案后，公共方案可以重新谈判，但不会保留已撤销的签字。两位议员支持的普通方案为 $32,000；再买高价包装为 $40,000。

## 三种结局与测试路线

**判定顺序：B → C → A，提交前始终先预览。** 听证会中间讲台上的 SUBMIT 文件需要两次互动。

1. **A 清廉结局**：收取任务文件与报价；保持 $2,000，不接受个人现金，前往听证会提交。预算被否决，评语为 “diligent, but lacks coordination skills”。若之前已经签过附加项目，先去承包商确认 PLAIN 恢复原方案再提交。
2. **B 共同进步结局**：收取文件与报价，确认 Doran 的 FACTORY 与 Bell 的 TRAINING，签字达到 2/2，再提交。普通椅方案共 $32,000；可选 STAR 将预算升到 $40,000。即使拿过个人现金，只要两人都支持，仍优先进入 B。最后：“Smith was promoted. The chairs have not arrived.”
3. **C 背锅结局**：收取文件与报价，去档案室北面的休息室，确认 ENVELOPE；在签字不足 2/2 时提交。可以零签字或只有一位议员支持。最后：“Everyone suddenly cares about public spending.”

如果没有拿现金、签字不足两份，但预算已经高于 $2,000，SUBMIT 会拒绝提交并告诉你继续谈妥两位议员，或恢复原方案。它不会把半成品误判成清廉结局，也不会锁死游戏。

第一次探索的设计目标是约 8–10 分钟；熟悉地图和决定后可以更快。此时长是设计目标，没有进行外部玩家计时实验。

## 原生数据与重新导入

使用真实、未修改的 Bitsy **8.15 RELEASE** 引擎。数据与 HTML 来自同一份最终 `game.bitsy`；HTML 内嵌 `exportedGameData`，不从网络另载数据。

1. 进入 [官方 Bitsy 编辑器](https://bitsy.org/)，或兼容 8.15 的本地编辑器。
2. 打开 **Game → data → load data**，选择 `game.bitsy`。也可以在游戏数据文本区粘贴整个文件，包含开头和最后的换行。
3. 检查房间列表为 8 个，点击 play 运行。之后可正常修改像素、房间和原生对话并导出。
4. 重新导出 HTML 时，官方编辑器会使用自己的外观；游戏规则与剧情仍由原生数据保留。无需保留本页面的 CSS 才能游玩。

关键状态均为原生变量：`budget`、`factory`、`training`、`premium`、`perk`、`refused`、`submitted`、`ending`、`pending`、`briefed`、`quotes`、`signatures`。物品负责一次性收文件；条件对话负责判断状态；玩家走向不同文件才构成主动选择。出口对话用原生 `property locked` 控制文件领取前的通行。没有把条件分支伪装成互动菜单。

## 文件说明

- `index.html`：完整离线游戏，内嵌引擎、字体、画面和最终数据。
- `game.bitsy`：可重新导入编辑器的原生数据，也是制作依据。
- `README.md`：操作、规则与三种结局路线。
- `GDD.md`：按模板七部分整理的英文设计文档。
- `GDD_Completed.docx`：填写后的 Word 模板；原模板在 `sources/` 中保留。
- `TEST_REPORT.md`：实际测试方式、覆盖范围和结果；区分自动引擎测试与真实浏览器检查。
- `sources/BITSY_LICENSE.md`、`sources/ENGINE_PROVENANCE.md`：引擎许可与固定版本记录。

## 课程与阅读

GDD 的理论部分只使用本项目已取得的 Huizinga《Homo Ludens》第一章，以及 Mia Consalvo《Cheating》课程材料；页码依据文件中印刷页核对，解读与本游戏的设计选择分别表述。需要补充的事实包括小组成员全名、实际分工、tutorial section，以及课程要求的最终提交信息。不会把生成内容冒充成员已经完成的个人分工。
